# Open questions, not completed results

Prepared after the current findings, 9 November 2026. None of the experiments below was run for this repository update. Each would need its own design and prospective decision rule.

## 1. Does the mismatch survive an ordinary research workflow?

The existing study requests first-answer code without external tools. A useful follow-up would compare that condition with source retrieval and a normal code-review cycle. Preserve the initial answer, revisions, retrieved source versions, time/cost, and final program behavior. Success after retrieval would narrow the deployment concern while identifying a practical remedy.

## 2. Can rule-version mistakes predict the direction of a timing error?

The current N-PORT floor suppresses information in the task period. Another regime could separate submission from public release, reversing the error from delay to premature access. This is an analytical possibility in the paper, not an observed cross-regime model result. A small, source-verified panel should require the relevant rule to be applicable to each historical date, and should include cases models can solve correctly.

## 3. What is the decision-level cost of withholding?

The metadata audit measures days, not money. A next study could use an independently fixed signal and genuine point-in-time holdings, compare availability policies, and separate information loss from strategy selection and transaction costs. A near-zero economic effect would be an informative result, not a reason to replace the strategy until a larger effect appears.

## 4. Can software enforce the availability contract?

A candidate implementation could represent report date, raw submission, and actual public release as distinct fields and validate eligibility with a versioned rule registry. Evaluate coverage, exceptions, maintainability, and failure modes against simple explicit-column baselines. The current paper does not introduce or validate such a software system.

## 5. Which lessons from the portfolio work transfer?

The homogeneous-holdings example suggests a test-design principle: an input should separate plausible incorrect implementations. A follow-up could systematically measure whether test suites detect seeded semantic faults across financial tasks. The analogy to disclosure timing motivates this question; it is not evidence that the two tasks share one model mechanism.

## Criteria for continuing

Prefer new independent evidence over additional manuscript length. Record predictions before results; retain correct answers and technical missingness; do not turn negative findings into success through post-hoc thresholds. A one-rule or one-configuration result can remain a useful narrow case study.
